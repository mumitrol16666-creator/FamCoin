# Исправления повторного аудита 63eb7df

Изменения не затрагивают боевую базу и не требуют SQL-миграции.

- Логическая цепочка операции объединяет `edited` и `restoredFrom`. Корзина
  предлагает только последнюю удалённую версию. Действующая копия блокирует
  повторное восстановление всех предшественников; возвраты находят покупку
  после любого числа восстановлений.
- Восстановление `repaymentReceived` проверяет текущий остаток требования.
- Три формы оплаты используют одну неизменяемую попытку: ID команды, ID
  операции, сумма, счёт и дата закрепляются до подтверждения. При неизвестном
  результате поля и закрытие формы блокируются, доступен безопасный повтор.
  Подтверждённый отказ до записи разрешает исправление данных. Завершённая
  оплата не мешает создать следующую реальную операцию на ту же сумму.
- Оплата плана и изменение статуса периода — серверные команды
  `payPlannedPeriod` / `setPlannedPeriodPaid`. Актуальный JSON читается под
  блокировкой владельца; предыдущие периоды сохраняются. Повторная оплата
  одного периода с другим ID отклоняется. Запись денег и флага атомарна.
- Закрытые кредиты исключаются из текущих платежей, но остаются в базе
  расчёта прогресса. Аналитика дней начинается с первой наблюдаемой даты.
- Чистый возврат показан отдельным столбцом вверх и отдельной легендой;
  финансово он по-прежнему уменьшает расход, а не создаёт доход.

## Проверки

Новые unit/widget-тесты покрывают повторные восстановления, связанные
возвраты, предел требования, потерю ответа и неизменность попытки, два
устаревших объекта сроков, прогресс после закрытия кредита, точную границу
истории и направление столбца. Серверные интеграционные тесты проверяют
двух клиентов на настоящем PostgreSQL и откат неуспешной оплаты.

Команды:

```sh
(cd packages/famcoin_core && dart pub get && dart test)
(cd app && flutter pub get && flutter gen-l10n && flutter test)
(cd server && dart pub get && dart test)
```

Интеграционные тесты включаются только с `FAMCOIN_INTEGRATION=1` и используют
одноразовую локальную БД `famcoin_test` из CI. Производственные URL и
секреты не считываются.

Ограничение: незавершённая попытка хранится в живой форме, а не в постоянном
outbox. После принудительного завершения приложения при неопределённом
результате нужно перечитать журнал перед повторным вводом. Для гарантии
через перезапуск потребуется отдельное защищённое хранилище попыток.

Развёртывать сначала сервер, затем приложение: старый сервер не знает новых
команд оплаты. Pull request сам по себе ничего не развёртывает.
